# E5 corrected (audit issues C1, M5)

Generated by tracks/fixes/e5/e5_report_fixed.py from e5_allocation_fixed.py / e5_auroc_fixed.py. Same 17 signals, 7 clusters, rules and 30 plain + 60 bootstrap splits as tracks/r2_t2/e5_new_streams.py.

**What changed.** (C1) Spend matching sweeps the level over B × {0, 0.01–3 log-spaced, 1} and interpolates at realized test spend = B only when B lies inside that split's realized-spend range; otherwise the split is unmatched (no clamping). Point estimates average matched plain splits; rows matched in < 80% of plain splits are reported as not estimable, because averaging only the splits that happen to reach B is a selected sample. (M5) Attacks are deduplicated by content hash, and the attack split is grouped by base attack (orig_traj_id; originals map to themselves) with a cluster bootstrap over base attacks. Selection safety uses the calibration attacks as attacker information, as in E5.

> **Confound:** 508 of 541 attacks (94%) are T3 refined rewrites whose tool outputs were fabricated by the refiner LLM; honest outputs and the 33 MonitoringBench originals' outputs are real. A signal can partly separate honest from refined attacks by keying on fabricated outputs or rewrite artifacts.

## Data and duplicates

- Attack set: 541 attacks (33 originals + 508 refined) from 148 base attacks. Identical-content groups in the E5 set: 0 (removed 0). The audit's '329 of 419 adaptive refined trajectories byte-identical to r0' is correct for the files (data/processed/t3_refined/<arm>/ re-lists the r0 trajectory under the same traj_id when the adaptive loop stopped at round 0), but E5 keys signals by traj_id, so those copies were already merged. The real leak was correlated variants (original, r0 under 3 arms, r1/r2) of one base attack falling on both sides of the split.
- Allocation clusters (honest / attacks / base attacks): c0 (43 / 40 / 13), c2 (213 / 173 / 42), c3 (65 / 63 / 16), c4 (47 / 78 / 25), c5 (73 / 109 / 29), c6 (64 / 52 / 16), c7 (30 / 21 / 6).
- Originals in the allocation clusters: c0 4, c2 15, c3 1, c4 2, c5 8, c6 1, c7 1. Too few for attack-fitted allocation (stack, maxdet), so originals-only results are AUROC and honest-only rules.

## Spend floor of per-context rules (C1)

Plug-in per-context thresholds at level 0 sit at each cluster's calibration maximum, so test honest runs above it still alarm. The realized test spend therefore has a floor of about Σ_c w_c / (n_c^cal + 1) = 2.52% with 15–106 calibration honest runs per cluster. Below the floor, 1% cannot be reached, so **1% spend-matched estimates are not estimable for cfar, stack, stack_m0 and maxdet**.
